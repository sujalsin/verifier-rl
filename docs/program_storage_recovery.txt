Evidence protocol
-----------------
1. Atomically write immutable test JSON to the work Volume (private temporary
   file, fsync, create-only hard link; a conflicting file fails closed).
2. Commit every 16 inputs and at program completion. Each candidate input is
   submitted at most once; storage retries never call candidate execution.
3. Commit the complete program document and an independent compact archive copy
   before publishing the final hash-bound Dict index. No per-test Dict writes.
4. Bound each storage RPC to 30 seconds, three attempts, delays of 1 and 3 seconds.
   Evidence conflicts are not retried. Exhaustion preserves evidence and stops.
5. A complete Volume result whose Dict publication failed is validated and
   republished without execution. A claimed but incomplete execution is never
   automatically resubmitted. Storage callback failures are explicitly labeled
   evidence_storage, not silently counted as candidate failures or zero reward.
6. Use one bounded unknown-counter update per program, not quadratic slot probes.
   Keep all historical unknown counters; migrate the active counter only after
   validating the exact recovered outcomes to which those counters refer.

Work Volume uses Modal v2; independent compact program backups use the existing
v1 evidence Volume. This is application-level redundancy, not a guarantee against
all provider/storage loss. Modal documents explicit commits and warns that v2 is
still beta: https://modal.com/docs/guide/volumes
