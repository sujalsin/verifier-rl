2026-09-27. The user approved the recommended sequence. This amends the earlier
SFT plan's binary-only readiness gate; it does not change historical evidence.

1. Validate a new balanced training suite offline, before any policy training.
   Version cache-balanced-probes-0.1; fixed seed 20260929. Six families with four
   cases each (24 total). Retrieval, expiry, overwrite, multiple keys and order
   each have weight .19; edge cases together have weight .05. Each substantive
   probe requires a stored integer and a missing/expired output. Edge probes
   retain empty, write-only, missing-only, and zero/negative-value behavior.
   Credit is exact correctness of a whole probe, not individual output elements.
   Partial reward = weighted mean of family pass fractions. Binary reward =
   all 24 probes correct. Both are derived from identical execution records.
   Existing G3 and development audit are unchanged. No syntax/format bonus.
   Candidate failure loses that probe; infrastructure failure leaves the entire
   candidate unscored. Expected answers and scoring remain outside the sandbox.

   Pre-specified controls at seeds 20260929..20260931: correct fixture scores 1;
   every existing semantic mutant fails full acceptance; always-None, always-[],
   constant-7 and seeded random-answer controls score at most .05. A functioning
   dictionary that ignores expiry must score strictly between .05 and 1.
   Finite checks bound these tested shortcuts, not all possible false acceptance.

2. Build the 32-train / 8-development non-cache SFT examples described in
   sft_warmstart_plan.txt. Fixed project-authored functions, four prompt variants
   per family, eight training and two held-out development families. Preserve
   provenance, source hashes, signature checks, and explicit reference tests.
   No cache/TTL code, cache cases, audit answers, or external generated corpus.
   The fixed trusted functions are tested directly; arbitrary generated code
   never executes on the laptop.

   One 16-step full-parameter SFT job on Qwen2.5-Coder-0.5B-Instruct at the
   existing pinned revision. Seed 20260930; lr 2e-5, weight decay 0, AdamW,
   constant schedule, batch 1, accumulation 4, float32 weights / bf16 compute,
   gradient checkpointing; maximum 1024 training tokens, no silent truncation.
   Prompt and padding labels are -100; genuine assistant EOS remains supervised.
   Validate string AND token-prefix alignment with the actual tokenizer.
   Evaluate teacher-forced train/dev loss before and after, without selecting
   checkpoints on it. Require finite gradients, changed parameter hash, and
   exact checkpoint reload identity. Loss alone is not coding performance.

   Generate eight before/eight after cache programs with the reminder prompt,
   paired seeds 4000..4007, temperature .8/top_p .95/top_k 0/512-token cap.
   Always load the real saved SFT checkpoint for the after condition. Grade
   both G3 and the balanced suite for readiness; up to 55 distinct inputs per
   candidate before cross-suite deduplication (880 maximum invocations).
   Report both binary and partial scores; never replace old G3 reward fields.
   No per-candidate repair, resampling, or retry. Stop on infrastructure errors.
   One L4 function capped at 900 seconds; separate hosted CPU controller capped
   at 1500 seconds, four paced workers. Persist each sample/report as it arrives.
